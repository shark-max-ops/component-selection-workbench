| 部分 | 做什么 | 意义 |
| --- | --- | --- |
| `scripts/run_terminal.py` | 启动命令循环 | 提供简短、稳定的运行入口 |
| `app/terminal.py` | 解析命令、管理当前任务、展示结果和进度 | 将用户操作转成服务调用；查询和未知命令不会误触模型 |
| `app/task_service.py` | 创建、查询、执行、校验和归档 | 终端共用 A1 业务链；首次执行传入用户消息，续聊保留原输入 |
| `app/events.py` | 在工具调用前后记录事件并通知终端 | 进度来自真实调用，能查到读了哪页、哪个工具失败 |
| `tests/test_terminal.py` | 检查命令分发与工具异常事件 | 验证交互控制，不冒充真实模型效果 |
| `tests/test_task_service.py` | 用真实图检查事件配对和业务续聊 | 验证事件接入没有破坏原业务与持久化 |

数据流：输入命令 → 终端分发 → 应用服务 → Harness → 事件中间件 → 真实工具 → 保存检查点 → 程序检查报告 → 终端分别显示模型解释和程序结果。

每条事件保存 task_id、run_id、sequence、time、type、payload。工具事件用 call_id 配对；并行调用可能交错，序号表示记录顺序。事件只保存工具名、路径等必要信息，不保存思维过程、密钥或完整工具内容。`tool_finished` 表示工具正常返回，不等于器件满足；业务拒绝原因还需查看工具消息与结构化报告。界面回调失败不改变业务结果，事件文件写入失败则使运行失败，不保证跨故障可靠重放。

每次运行归档位于 `runtime/persistent_tasks/<task_id>/runs/<run_id>/`，新增 `events.jsonl`；原消息、业务记录、报告和 manifest 继续保存。查询不生成运行事件。模型解释没有新增自动语义验收，不能高于程序报告。

退出行为：`/exit` 和输入结束关闭终端；Ctrl+C 中断时提示可能存在未完成节点，不承诺任意节点恢复，也不自动重试。连接失败只记录运行失败，不改变器件判定；任务有未完成节点时后续执行仍按 A1 规则拒绝。
