# B1 资料库：导入、解析、版本和旧数据索引

## 普通人怎样理解

`library/` 是资料档案室，`runtime/` 仍是任务运行记录。导入时先给 PDF 建登记卡：厂家、型号、资料类型、文档编号、修订、来源、时间、哈希、页数、解析状态各有自己的字段。原件放 `originals/<哈希>/source.pdf`；PyMuPDF 逐页文本放 `extracted/<哈希>/page-0001.txt` 等；SQLite `catalog.sqlite` 记住它们的关系。相同文件再导入直接复用；同编号的不同修订按不同哈希保存，旧版不覆盖新版。

每页有 `parsed` 或 `empty_or_scanned` 状态，损坏 PDF 为 `failed` 并留下错误。页面全文作为最小片段，保留该页表格上下文与脚注；编号章节只是标题提示，不能保证页面只属于这一个章节。页码是 PDF 从 1 开始的页序，区域坐标尚未验证。正式证据仍须抽查原版 PDF。

资料库在 `library/cards/` 导出 ADS1115、ADS1015、MCP3208 三张可直接打开的 Markdown 短简介；SQLite `part_cards` 同步保存可查询文本和来源。每张都写明绑定手册，供 B2 快速找候选；它们不是参数已通过的证明。`wiki/` 只是预留目录，完整 Wiki 属于 B4。

## 解析器比较与选择

`markitdown[pdf]` 已通过 uv 锁定和安装，在五份真实资料上转换成功，生成 `markitdown.md`，SQLite 的 `parser_runs` 保存版本、配置、状态及 `page_mapping=unmapped`。它适合浏览，但整份转换没有可靠逐页映射；MCP3208 的吞吐量表在 Markdown 中被拆成不易判读的多行。因此 B1 选择 **PyMuPDF 逐页文本作为正式证据定位基线**；MarkItDown 仅是候选阅读格式，不自动生成 Evidence。关键数值、脚注和跨页条件仍需要 PDF 核对。扫描页目前不做 OCR。

## 旧数据与回退

`index-legacy` 只读 `runtime/persistent_tasks/` 的 JSON 和审核 SQLite，在 `catalog.sqlite` 建立任务、运行、证据、事实、审核、报告的可查询元信息索引；原文件和旧数据库均不搬迁。重复执行按标识更新，不增加重复有效行。本轮实际索引 3 个任务、11 次运行、2 条审核。后续新任务若仍走 A 阶段入口，需要重跑索引才能更新此目录；B2 接入时再统一写入路径。

回退办法：停止使用 `library/catalog.sqlite` 即可继续运行 A 阶段；若只想撤销旧数据索引，可备份该 SQLite 后清空六个 `*_index` 表。原始 `runtime/` 任务始终保留，不依赖新索引。解析产物可由原 PDF 重建，不能把它们当唯一原件。

## 用 uv 查看

在 `backend` 目录执行：

```powershell
uv run python -B -m scripts.library list
uv run python -B -m scripts.library summary
uv run python -B -m scripts.library cards
uv run python -B -m scripts.library pages 文档ID
uv run python -B -m scripts.library compare 文档ID
uv run python -B -m scripts.library index-legacy
```

导入新增 PDF 时，先从首页核对元数据，再执行：

```powershell
uv run python -B -m scripts.library import PDF路径 --manufacturer 厂家 --kind datasheet --part 型号 --number 文档编号 --revision 修订号 --url 来源网址
```

`list` 应显示 5 份文档、编号/修订分列；重新导入同一文件返回 `reused: true`。`summary` 当前显示 5 份文档、238 页、3 张器件卡、3 个旧任务、11 次运行、2 条审核。`pages` 可看到旧 C 版四页未提取状态；`compare` 明示 Markdown `page_mapping: unmapped`。B1 的程序测试验证去重、版本共存、空白页、坏 PDF、MarkItDown 来源限制和旧数据只读索引；完整回归 **79 passed**。
